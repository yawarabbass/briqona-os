Account recovery and security

Password recovery should always be handled through a secure authentication backend. This page currently provides the frontend experience only.

  • Recovery links should be short-lived and single-use.
  • Passwords should never be stored in plain text.
  • Recovery requests should use secure, server-side verification.
  • Account information should not be exposed through recovery responses.
  • HTTPS should be used for production authentication traffic.
  • Rate limiting can help protect recovery endpoints from abuse.
